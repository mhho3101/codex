# adapters · 数据源接入约定

> content-director 引擎不直接采集平台数据。对标样本、回标数据、热点候选都通过 adapter 接入——
> 你用任何下载/统计工具（yt-dlp、平台后台导出、第三方数据工具均可）取数，按本契约的格式落到客户目录。

## 1. 对标成对样本（标准挖掘 S3 的输入）

落到 `clients/<id>/03-benchmarks.md` 的「成对样本区」，每对两侧各一条：

| 字段 | 说明 | 必填 |
| --- | --- | --- |
| 侧别 | 爆款 / 普通 | ✅ |
| 视频 ID | 平台作品 ID | ✅ |
| 公开链接 | 可核对的公开 URL | ✅ |
| 互动数据 | 点赞/收藏/评论/转发（公开数据） | ✅ |
| 钩子机制 | 开头用了什么体（一句话） | ✅ |
| 逐字稿路径/摘要 | 本地路径或摘要 | ✅ |

**选取规则**：同账号内互动显著高于该账号均值 → 爆款侧；均值附近 → 普通侧。双方均须拿到逐字稿或完整文案；拿不到的样本不进成对区（可作标题级弱证据另存）。

**异常爆款优先**：粉丝少但单条播放远高于自身均值/粉丝数的样本，信号最强。

## 2. 回标数据（模块 E 的输入）

发布 3 天后回填到 `clients/<id>/02-scripts.md` 对应条目：

```text
- 实际数据：播放 __ ｜ 完播 __% ｜ 点赞 __ ｜ 收藏 __ ｜ 分享 __ ｜ 评论 __ ｜ 线索 __
```

`metrics` 与 `aha` 命令只认这个格式。播放量支持 `5000` / `3.2万` / `5w` 写法。

## 3. 热点候选（trends 的输入）

落到 `clients/<id>/01-topics.md` 候选区，一行一条：

```text
- [YYYY-MM-DD] 候选句 ｜ 来源：热点/搜索/评论/对标 ｜ 时效：24h/本周/长期 ｜ 相关度：高/中/低+理由 ｜ 状态：待评
```

规则见 `references/trends-and-candidates.md`。

## 边界

- 不接平台 API、不存 Cookie/凭证/签名链接进任何客户文件；
- 样本只借鉴机制，不复制原句/标志性案例/个人经历；
- adapter 实现（爬虫/导出脚本）不进本包——本包只定义输入契约。
