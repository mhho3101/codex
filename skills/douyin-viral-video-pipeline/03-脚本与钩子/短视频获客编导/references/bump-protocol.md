# 标准卡升级协议（bump）

> 对应命令：`director.py bump <cid>` 生成重打工作表。
> 一句话：**改标准不是改文件，是一次全量重打 + 独立审核的实验。**

## 触发条件

- 校准池（有回标数据的样本）≥ 5 条；
- 且出现以下之一：同一方向连续 3 次偏差 / 月度例行回修 / 明确的新强信号出现。

## 升级流程（顺序不可乱）

1. **写新公式**：在标准卡草稿区写出权重调整（每项必须有理由 + 来源样本）；
2. **全量重打**：用新公式对校准池**所有**样本重新打分（`bump` 命令生成工作表：每样本列出旧分/新分/实际表现档）；
3. **一致性校验**：新公式的排序与实际表现排序相比——若 ≥4/5 的样本排序不一致，**升级被拒**；
4. **独立审核**：换一个模型/会话来审（主生成模型不能自审）；
5. 通过后写入 `06-standard.md`，记录 bump 版本行；不通过则保留旧版，调整理由写入学习日志。

## 观察生命周期（rubric 是工作台，不是博物馆）

- 被新数据**推翻**的观察 → 删掉；
- 被**吸收**为正式维度的观察 → 删掉备注层，只留正式维度；
- 不留"我曾经以为 X，但其实……"的考古层——git history 才是档案；
- 每次 bump 后标准卡只保留当前最有用的权重与偏好。

## Refusals

- 「跳过全量重打，直接换公式」→ 拒绝。
- 「跳过独立审核，自己说了算」→ 拒绝（除非用户显式声明自审并承担风险，且记入 bump 记录）。
- 「把阈值从 4/5 降到 3/5 让这次 bump 过」→ 拒绝。改阈值本身是元层级 bump，单独走流程。
- 「历史观察都留着，加时间戳分组就行」→ 拒绝。违反生命周期规则。
