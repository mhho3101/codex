# 盲预测与拍发分离（模块 D/E 用）

> 对应命令：`predict` / `shoot` / `publish` / `retro`。
> 一句话：**预测写于看到数据之前，写完不可改；拍了和发了是两件事，buffer 过高先发布。**

## 原则 1：盲预测 immutable

- 预测必须在看到任何实际数据**之前**写完（`director.py predict <cid> <slug>`）。
- 写完的 `## 预测` 段**不可改**：要修正只能新开 `_redo.md`，原版保留。
- Claude Code 用户可用 `hooks/` 里的样例 hook 物理拦截对 predictions/ 的直接编辑；其他 harness 靠纪律 + CLI 设计（引擎不提供编辑预测段的命令）。
- **拒绝**「我先告诉你播放量，你反推一下预测」——那是 reconstructed，不是 prediction。

## 原则 2：拍 ≠ 发（buffer 警戒）

- `shoot <cid> <slug>`：登记"已拍未发"，buffer +1；
- `publish <cid> <slug>`：登记"已发布"，buffer -1；
- buffer 颜色（写在 `05-state.md`）：
  - 0 = 绿：正常排产；
  - 1-2 = 黄：优先发库存，新拍摄放缓；
  - ≥3 = 红：**停止新拍摄，先发布**——库存积压说明执行节奏断了。

## 原则 3：retro 只追加

- 发布 3 天后 `director.py retro <cid> <slug>`：只在 `## 复盘` 段追加，绝不动 `## 预测` 段；
- 复盘字段：实际数据（播放/完播/赞/藏/转/评/线索）+ 偏差分析（预测 vs 实际差在哪）+ 复用结论；
- 复盘结论喂给 Aha 判级（data-loop.md）和标准卡回修（bump-protocol.md）。

## 节奏协议（recommend 命令用）

推荐下一批选题时看 buffer 颜色：

| buffer | 推荐策略 |
| --- | --- |
| 绿（0） | 1 条稳健（已验证钩子/方向）+ 1 条实验（新角度） |
| 黄（1-2） | 只推 1 条稳健；提示先发库存 |
| 红（≥3） | 不推荐新选题；只给"先发布"提醒 |

## Refusals（本卡范围的必须拒绝）

- 「预测写错了，帮我改一下」→ 拒绝。新开 `_redo.md`，原版保留。
- 「先别登记 shoot，等发了再说」→ 拒绝。buffer 失真会导致节奏误判。
- 「这条没数据也复盘一下」→ 拒绝。无数据复盘=编造，等数据或标记失败。
- 「buffer 到 5 了但我还是想拍新的」→ 提示红灯，由用户决策，不默默执行。
