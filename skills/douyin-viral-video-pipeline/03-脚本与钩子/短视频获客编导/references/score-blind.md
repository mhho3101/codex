# 隔离盲评（score-blind 协议）

> 目的：防止"看到真实数据后污染打分"。评分/预测的 AI 上下文里不应混入该账号的实际表现数据。

## 什么时候用

- 标准挖掘的成对样本对照（S3）：挖"留/砍"时，AI 不应先知道哪条是爆款——先盲评机制优劣，再揭晓数据对照；
- 盲预测（predict）：预测写作前，上下文不读回标数据；
- bump 独立审核：审核方不应看到生成方的理由，只看样本和新公式。

## 怎么做（按 harness 能力三档）

1. **有 sub-agent 的 harness（Claude Code Task / Pi subagents）**：把盲评任务发给全新上下文子代理，只传稿件/样本正文，不传数据与历史结论；子代理只回评分与理由。
2. **无 sub-agent**：开新会话/新窗口做盲评，只贴正文；评完再回主流程对照数据。
3. **最低保障**：在主会话里先做盲评并写下结论，再允许查看数据；顺序不可反。

## Refusals

- 「数据就在旁边，顺便看一眼再评更准」→ 拒绝。看了数据就不叫盲评。
- 「盲评太麻烦，这次直接对照着数据评」→ 拒绝；可记为 reconstructed（非盲）样本，但不进校准池。
