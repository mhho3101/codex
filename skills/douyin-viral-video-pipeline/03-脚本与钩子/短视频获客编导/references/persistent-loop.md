# 常驻循环：每客户状态机（v2 核心）

> 适用：任何客户任务进来时先读本卡。判断该客户处于哪个状态、本次该进哪一步。

## 设计转变

编导 Agent 不是"跑一次出方案就结束"的一次性工作流，而是**每客户一个常驻循环**：从定位到找到账号 Aha Moment、不断复利；客户没反馈时挂起写代办，不空转、不假装推进。

## 状态机（六态）

```text
[*] → 待定位确认（新客户接入，出定位方案发客户）
待定位确认 → 冷启动选题（客户确认定位）
待定位确认 → 待定位确认（未确认→写代办，定时催办）
冷启动选题 → 脚本生产（选题过闸门）
脚本生产 → 待拍摄发布（交付）
待拍摄发布 → 回标评估（客户发数据/巡检）
回标评估 → 拍穿放大（A 级 Aha：≥2 条超基线+强反馈）
回标评估 → 冷启动选题（B 级改钩再测 / C 级归档换方向）
拍穿放大 → 回标评估（每批变体数据回来）
拍穿放大 → 冷启动选题（流量衰退→沉淀资产与复盘→找下一个 Aha）
```

每个状态都落盘在 `clients/<id>/05-state.md`（运行状态文件）；换会话、换人、换 Agent 都从状态继续，不从零开始。

## 事件与唤醒

| 事件 | 用户原话 | Agent 动作 |
| --- | --- | --- |
| E1 确认定位 | "定位没问题" | 状态→冷启动选题 |
| E2 发素材 | "素材发你了" | 补缺口→脚本生产；缺口过大（影响选题成立）→回调选题 |
| E3 数据回来 | "数据来了/复盘一下" | 状态→回标评估 |
| E4 提问 | "今天拍什么" | 读运行状态→对应下一步 |
| E5 定时巡检 | 每日/每周任务 | 扫代办清单到期项→催办/进入回标评估 |
| E6 新客户 | "给 XX 建号" | 建五件套→出定位方案→等确认 |

## 挂起与代办机制

- 五类"等客户"动作：定位确认 / 素材 / 数据 / 对标账号 / 发布链接。
- 一律写进 `clients/<id>/04-learning.md` 待办区：条目含**等什么、期限、催办方式**；运行状态置"等客户（挂起）"，Agent 不空转。
- 定时巡检（每日/每周）扫代办：到期未回→催办；数据已回→唤醒进回标评估。
- 连续挂起超期（如 15 天无反馈）→ 标记"待决策"，不自动继续。

## 冷启动 vs 数据驱动（两阶段）

**冷启动（第一批，无客户数据）**：选题来源 = 联网搜索（行业关键词/热点/客户相关话题）+ 对标研究（公开样本）；评分用**通用 8 项表**（首轮无专属权重），≥11 进排期。

**数据驱动（有回标后）**：专属权重（见 `standard-mining.md`）+ Aha 假设库参与评分；每轮对照账号基准线（近 10 条均值）判断方向。

## 人工闸门（判断留人的落点）

| 闸门 | 位置 | 人干什么 |
| --- | --- | --- |
| 定位确认 | 定位方案后 | 客户/用户点头（未确认→代办） |
| 对标清单确认 | 找对标后 | 确认候选同赛道、体量适合 |
| 标准挖掘结果 | 挖出权重后 | 审 AI 挖出的权重/偏好，防噪声成规则 |
| 交付 | 交付包后 | 拍板交付，写入客户目录 |
| 发布前合规 | 发布前 | 排期+合规复核 |

机器可判的闸门（评分≥11、四关、来源非空）自动放行，不过则回炉，**每类闸门回炉上限 2 轮，超限转人工**——防无限循环。

## 运行状态文件纪律

1. 每次唤醒（E1-E6）先读 `05-state.md`，再决定进哪一步。
2. 每个闸门通过/打回、每次挂起/恢复，立即回写本文件。
3. 回炉计数每次打回 +1；进入下一步时清零上一闸门计数。
4. 状态变更必须留一行轨迹：`日期 事件 → 新状态（原因）`。

## 成功判据

找到该账号的 **Aha Moment**：至少 2 条明显高于账号基准线（近 10 条均值）且评论/转化强反馈，进入拍穿计划。判级细则见 `data-loop.md` §Aha判级。
